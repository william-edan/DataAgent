# 员工档案查询知识库

## 📋 核心原则

**当用户查询以下内容时，必须同时查询 oa_admin 和 oa_admin_profiles 两个表**：
- "员工档案"
- "员工档案信息"
- "完整档案"
- "详细档案"
- "员工详细资料"
- "员工完整信息"
- "员工履历"

## 🗂️ 表结构说明

### oa_admin 表（员工基本信息表）

**用途**：存储员工的当前状态信息，包括组织关系、岗位信息、基本属性。

**核心字段**：
- `id` - 员工ID（主键）
- `name` - 员工姓名
- `mobile` - 手机号码
- `email` - 电子邮箱
- `did` - 所属部门ID
- `position_name` - 职务
- `position_rank` - 职级
- `type` - 员工类型（0未设置，1正式，2试用，3实习）
- `is_staff` - 身份类型（1企业员工，2劳务派遣，3兼职员工）
- `age` - 年龄
- `sex` - 性别
- `idcard` - 身份证
- `education` - 学位
- `entry_time` - 入职日期
- `status` - 状态（-1待入职，0禁止登录，1正常，2离职）

### oa_admin_profiles 表（员工档案详情表）

**用途**：存储员工的历史记录信息，包括教育经历、工作经历、证书、技能等。

**核心字段**：
- `id` - 档案记录ID（主键）
- `admin_id` - 员工ID（外键，关联 oa_admin.id）
- `types` - 类型（1教育经历，2工作经历，3相关证书，4计算机技能，5语言能力）
- `title` - 院校/公司名称/证书名称/技能名称
- `speciality` - 所学专业
- `education` - 所获学历
- `position` - 职位
- `authority` - 颁发机构
- `start_time` - 开始时间
- `end_time` - 结束时间
- `know` - 熟悉程度
- `remark` - 备注说明

**重要特点**：
- 一个员工可能有多条档案记录（多段教育经历、多个工作经历、多个证书等）
- 通过 `types` 字段区分不同类型的档案信息

### 表关联关系

```
oa_admin.id = oa_admin_profiles.admin_id
关联类型: 一对多（一个员工有多条档案记录）
```

## 📊 标准查询模板

### 模板1: 查询员工完整档案（推荐）

```sql
SELECT
  -- 基本信息
  a.id AS 员工ID,
  a.name AS 姓名,
  a.mobile AS 手机号,
  a.email AS 邮箱,
  a.sex AS 性别,
  a.age AS 年龄,
  a.idcard AS 身份证,

  -- 组织岗位信息
  a.did AS 部门ID,
  a.position_name AS 职务,
  a.position_rank AS 职级,
  a.type AS 员工类型,
  a.is_staff AS 身份类型,
  a.status AS 状态,
  a.entry_time AS 入职日期,

  -- 档案详情
  p.id AS 档案记录ID,
  p.types AS 档案类型,
  p.title AS 标题,
  p.speciality AS 专业,
  p.education AS 学历,
  p.position AS 职位,
  p.authority AS 颁发机构,
  p.start_time AS 开始时间,
  p.end_time AS 结束时间,
  p.know AS 熟悉程度,
  p.remark AS 备注
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工'
ORDER BY a.id, p.types, p.start_time DESC;
```

### 模板2: 查询员工基本信息（仅基础字段）

**适用场景**：用户明确只要"基本信息"，不需要档案详情

```sql
SELECT
  id, name, mobile, email, sex, age,
  did, position_name, position_rank,
  type, is_staff, status, entry_time
FROM oa_admin
WHERE name = '员工';
```

### 模板3: 按档案类型筛选

**教育经历**：
```sql
SELECT a.name, a.position_name,
       p.title AS 院校, p.speciality AS 专业,
       p.education AS 学历, p.start_time, p.end_time
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工' AND p.types = 1;
```

**工作经历**：
```sql
SELECT a.name, a.position_name,
       p.title AS 公司, p.position AS 职位,
       p.start_time, p.end_time, p.remark
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工' AND p.types = 2;
```

**相关证书**：
```sql
SELECT a.name, a.position_name,
       p.title AS 证书名称, p.authority AS 颁发机构,
       p.start_time AS 获得时间
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工' AND p.types = 3;
```

## 🎯 常见查询场景

### 场景1: 按姓名查询员工档案

**用户查询**：
- "查询员工姓名为 张三 的档案信息"
- "张三的员工档案"
- "查看张三的完整档案"

**生成 SQL**：
```sql
SELECT a.*, p.*
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '张三'
ORDER BY p.types, p.start_time DESC;
```

### 场景2: 按部门查询员工档案

**用户查询**：
- "查询技术部所有员工的档案"
- "部门ID为10的员工档案"

**生成 SQL**：
```sql
SELECT a.*, p.*
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.did = 10
ORDER BY a.id, p.types;
```

### 场景3: 按职级查询员工档案

**用户查询**：
- "查询所有P7及以上员工的档案"
- "职级为P6的员工档案信息"

**生成 SQL**：
```sql
SELECT a.*, p.*
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.position_rank IN ('P7', 'P8', 'P9')
ORDER BY a.position_rank DESC, a.id;
```

### 场景4: 查询教育背景

**用户查询**：
- "查询张三的教育经历"
- "员工的学历信息"

**生成 SQL**：
```sql
SELECT a.name, a.position_name,
       p.title AS 院校, p.speciality AS 专业,
       p.education AS 学历, p.start_time, p.end_time
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '张三' AND p.types = 1
ORDER BY p.start_time DESC;
```

### 场景5: 查询工作经历

**用户查询**：
- "张三的工作经历"
- "员工的职业履历"

**生成 SQL**：
```sql
SELECT a.name, a.position_name,
       p.title AS 公司, p.position AS 职位,
       p.start_time, p.end_time, p.remark AS 工作描述
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '张三' AND p.types = 2
ORDER BY p.start_time DESC;
```

## ⚠️ 重要注意事项

### 1. 数据特点
- **一对多关系**：一个员工在 oa_admin 中只有一条记录，但在 oa_admin_profiles 中可能有多条记录
- **档案类型**：通过 types 字段区分（1教育/2工作/3证书/4技能/5语言）
- **时间排序**：档案记录建议按 start_time DESC 排序，显示最新的记录在前

### 2. 查询性能
- 使用 LEFT JOIN 确保即使员工没有档案记录也能查出基本信息
- 对于大量数据，建议添加 LIMIT 限制返回行数
- 索引：确保 oa_admin_profiles.admin_id 有索引

### 3. 字段映射

**员工类型（type）**：
- 0 = 未设置
- 1 = 正式员工
- 2 = 试用员工
- 3 = 实习生

**身份类型（is_staff）**：
- 1 = 企业员工
- 2 = 劳务派遣
- 3 = 兼职员工

**员工状态（status）**：
- -1 = 待入职
- 0 = 禁止登录
- 1 = 正常
- 2 = 离职

**档案类型（types）**：
- 1 = 教育经历
- 2 = 工作经历
- 3 = 相关证书
- 4 = 计算机技能
- 5 = 语言能力

### 4. 特殊处理

**去重处理**（仅需基本信息时）：
```sql
SELECT DISTINCT a.*
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工';
```

**统计档案数量**：
```sql
SELECT a.name, a.position_name,
       COUNT(p.id) AS 档案记录数,
       SUM(CASE WHEN p.types = 1 THEN 1 ELSE 0 END) AS 教育经历数,
       SUM(CASE WHEN p.types = 2 THEN 1 ELSE 0 END) AS 工作经历数,
       SUM(CASE WHEN p.types = 3 THEN 1 ELSE 0 END) AS 证书数
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工'
GROUP BY a.id, a.name, a.position_name;
```

## 📝 查询决策流程

```
用户查询包含以下关键词？
├─ "档案" / "档案信息" / "完整信息" / "详细资料" / "履历"
│  └─ 是 → 使用 LEFT JOIN 关联两表查询
│
├─ "基本信息" / "简要信息" / "概况"
│  └─ 是 → 仅查询 oa_admin 表
│
├─ "教育" / "学历" / "毕业"
│  └─ 是 → 关联查询，筛选 types = 1
│
├─ "工作经历" / "职业经历" / "简历"
│  └─ 是 → 关联查询，筛选 types = 2
│
└─ "证书" / "资质" / "资格证"
   └─ 是 → 关联查询，筛选 types = 3
```

## 🔍 示例对话

**Q**: 查询员工姓名为"员工"的档案信息
**A**: 生成关联查询 SQL，返回基本信息 + 所有档案记录

**Q**: 查询员工姓名为"员工"的基本信息
**A**: 仅查询 oa_admin 表

**Q**: 查询员工姓名为"员工"的教育经历
**A**: 关联查询，筛选 types = 1

**Q**: 查询所有正式员工的档案
**A**: 关联查询，筛选 a.type = 1

## 💡 最佳实践

1. **默认使用关联查询**：当用户说"档案"时，优先使用 LEFT JOIN
2. **明确字段选择**：避免使用 `SELECT *`，明确列出需要的字段
3. **适当排序**：档案记录按类型和时间排序，便于阅读
4. **处理空值**：使用 LEFT JOIN 确保基本信息总是能查出来
5. **性能考虑**：大量数据时添加 LIMIT，避免返回过多行
