# 员工档案查询知识库

## 📋 核心原则

**当用户查询以下内容时，必须同时查询 oa_admin 和 oa_admin_profiles 两个表**：
- "员工档案"
- "员工档案信息"
- "完整档案"
- "详细档案"
- "员工详细资料"
- "员工完整信息"
- "员工履历"

## 🚨 SQL 生成规则（必须遵守）

1. **禁止使用 AS 中文别名**：不要写 `a.id AS 员工ID`，直接写 `a.id`。系统会自动将原始字段名映射为中文显示名。
2. **避免同名字段冲突**：oa_admin 和 oa_admin_profiles 都有 `id` 和 `education` 字段，JOIN 查询时：
   - **不要选择 `p.id`**（档案记录内部ID，对用户无意义）
   - **不要同时选择两个表的 `education`**，只选 `p.education`（档案中的学历信息更完整）
3. **使用原始字段名**：所有字段直接用数据库原始列名（如 `a.name`、`p.types`），不加任何 AS 别名。
4. **必须包含 `p.types` 字段**：JOIN 查询时一定要选择 `p.types`，这是档案类型的分组依据字段。系统会自动按 `types` 将档案记录聚合为"教育经历"、"工作经历"、"相关证书"等分组返回。
5. **排序必须以 `p.types` 优先**：使用 `ORDER BY p.types, p.start_time DESC`，确保同类型记录连续排列，便于分组展示。

## 🗂️ 表结构说明

### oa_admin 表（员工基本信息表）

**用途**：存储员工的当前状态信息，包括组织关系、岗位信息、基本属性。

**核心字段**：
- `id` - 员工ID（主键）
- `name` - 员工姓名
- `mobile` - 手机号码
- `email` - 电子邮箱
- `did` - 所属部门（存储的是部门ID，需要关联 oa_department 表获取部门名称）
- `pid` - 上级主管（存储的是员工ID，需要关联 oa_admin 表自身获取主管姓名）
- `position_id` - 职位（存储的是职位ID，需要关联 oa_position 表获取职位名称）
- `position_name` - 职务（存储的是职务ID，需要关联 oa_basic_user 表 types=1 获取职务名称）
- `position_rank` - 职级（存储的是职级ID，需要关联 oa_basic_user 表 types=2 获取职级名称）
- `type` - 员工类型（0未设置，1正式，2试用，3实习）
- `is_staff` - 身份类型（1企业员工，2劳务派遣，3兼职员工）
- `age` - 年龄
- `sex` - 性别
- `idcard` - 身份证
- `education` - 学位
- `entry_time` - 入职日期
- `status` - 状态（-1待入职，0禁止登录，1正常，2离职）

### 关联查找表

**oa_department 表（部门表）**：
- `id` - 部门ID
- `title` - 部门名称

**oa_basic_user 表（人事基础数据表）**：
- `id` - 记录ID
- `types` - 数据类型：1=职务，2=职级
- `title` - 名称

**oa_position 表（职位表）**：
- `id` - 职位ID
- `title` - 职位名称

**⚠️ 重要**：`did`、`pid`、`position_id`、`position_name`、`position_rank` 字段存储的是ID而非名称，查询时必须用子查询转换为实际名称：
```sql
(SELECT d.title FROM oa_department d WHERE d.id = a.did LIMIT 1) AS did,
(SELECT m.name FROM oa_admin m WHERE m.id = a.pid LIMIT 1) AS pid,
(SELECT p.title FROM oa_position p WHERE p.id = a.position_id LIMIT 1) AS position_id,
(SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_name LIMIT 1) AS position_name,
(SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_rank LIMIT 1) AS position_rank
```

### oa_admin_profiles 表（员工档案详情表）

**用途**：存储员工的历史记录信息，包括教育经历、工作经历、证书、技能等。

**核心字段**：
- `id` - 档案记录ID（主键）
- `admin_id` - 员工ID（外键，关联 oa_admin.id）
- `types` - 类型（1教育经历，2工作经历，3相关证书，4计算机技能，5语言能力）
- `title` - 院校/公司名称/证书名称/技能名称
- `speciality` - 所学专业
- `education` - 所获学历
- `position` - 职位
- `authority` - 颁发机构
- `start_time` - 开始时间
- `end_time` - 结束时间
- `know` - 熟悉程度
- `remark` - 备注说明

**重要特点**：
- 一个员工可能有多条档案记录（多段教育经历、多个工作经历、多个证书等）
- 通过 `types` 字段区分不同类型的档案信息

### 表关联关系

```
oa_admin.id = oa_admin_profiles.admin_id
关联类型: 一对多（一个员工有多条档案记录）
```

## 📊 标准查询模板

### 模板1: 查询员工完整档案（推荐）

**注意：不使用 AS 中文别名，不选择 p.id，不选择 a.education（避免与 p.education 冲突）**

```sql
SELECT
  a.id, a.name, a.mobile, a.email, a.sex, a.age, a.idcard,
  (SELECT d.title FROM oa_department d WHERE d.id = a.did LIMIT 1) AS did,
  (SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_name LIMIT 1) AS position_name,
  (SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_rank LIMIT 1) AS position_rank,
  a.type, a.is_staff, a.status, a.entry_time,
  p.types, p.title, p.speciality, p.education, p.position, p.authority,
  p.start_time, p.end_time, p.know, p.remark
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工'
ORDER BY a.id, p.types, p.start_time DESC;
```

### 模板2: 查询员工基本信息（仅基础字段）

**适用场景**：用户明确只要"基本信息"，不需要档案详情

```sql
SELECT
  id, name, mobile, email, sex, age,
  (SELECT d.title FROM oa_department d WHERE d.id = oa_admin.did LIMIT 1) AS did,
  (SELECT b.title FROM oa_basic_user b WHERE b.id = oa_admin.position_name LIMIT 1) AS position_name,
  (SELECT b.title FROM oa_basic_user b WHERE b.id = oa_admin.position_rank LIMIT 1) AS position_rank,
  type, is_staff, status, entry_time
FROM oa_admin
WHERE name = '员工';
```

**教育经历**：
```sql

       (SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_name LIMIT 1) AS position_name,
       p.title, p.speciality, p.education, p.start_time, p.end_time
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工' AND p.types = 1;
```

**工作经历**：
```sql

       (SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_name LIMIT 1) AS position_name,

FROM oa_admin a
```

**相关证书**：

## ⚠️ 重要注意事项

### 1. 数据特点
- **一对多关系**：一个员工在 oa_admin 中只有一条记录，但在 oa_admin_profiles 中可能有多条记录
- **档案类型（核心分组字段）**：`types` 是 oa_admin_profiles 表的分类字段，系统会按此字段自动聚合返回：
  - 1 = 教育经历
  - 2 = 工作经历
  - 3 = 相关证书
  - 4 = 计算机技能
  - 5 = 语言能力
- **时间排序**：档案记录建议按 start_time DESC 排序，显示最新的记录在前
- **预期返回结构**：查询员工档案时，系统自动将结果拆分为：
  - 主表数据（oa_admin）：员工基本信息（姓名、手机、职务等），单条记录
  - 嵌套数据（oa_admin_profiles）：按 `types` 分组的档案详情（教育经历组、工作经历组等），每组多条记录

### 2. 查询性能
- 使用 LEFT JOIN 确保即使员工没有档案记录也能查出基本信息
- 对于大量数据，建议添加 LIMIT 限制返回行数
- 索引：确保 oa_admin_profiles.admin_id 有索引

### 3. 字段映射

**员工类型（type）**：
- 0 = 未设置
- 1 = 正式员工
- 2 = 试用员工
- 3 = 实习生

**身份类型（is_staff）**：
- 1 = 企业员工
- 2 = 劳务派遣
- 3 = 兼职员工

**员工状态（status）**：
- -1 = 待入职
- 0 = 禁止登录
- 1 = 正常
- 2 = 离职

**档案类型（types）**：
- 1 = 教育经历
- 2 = 工作经历
- 3 = 相关证书
- 4 = 计算机技能
- 5 = 语言能力

### 4. 特殊处理

**去重处理**（仅需基本信息时）：
```sql
SELECT DISTINCT a.*
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工';
```

**统计档案数量**：
```sql
SELECT a.name,
       (SELECT b.title FROM oa_basic_user b WHERE b.id = a.position_name LIMIT 1) AS position_name,
       COUNT(p.id) AS 档案记录数,
       SUM(CASE WHEN p.types = 1 THEN 1 ELSE 0 END) AS 教育经历数,
       SUM(CASE WHEN p.types = 2 THEN 1 ELSE 0 END) AS 工作经历数,
       SUM(CASE WHEN p.types = 3 THEN 1 ELSE 0 END) AS 证书数
FROM oa_admin a
LEFT JOIN oa_admin_profiles p ON a.id = p.admin_id
WHERE a.name = '员工'
GROUP BY a.id, a.name, a.position_name;
```

## 📝 查询决策流程

```
用户查询包含以下关键词？
├─ "档案" / "档案信息" / "完整信息" / "详细资料" / "履历"
│  └─ 是 → 使用 LEFT JOIN 关联两表查询
│
├─ "基本信息" / "简要信息" / "概况"
│  └─ 是 → 仅查询 oa_admin 表
│
├─ "教育" / "学历" / "毕业"
│  └─ 是 → 关联查询，筛选 types = 1
│
├─ "工作经历" / "职业经历" / "简历"
│  └─ 是 → 关联查询，筛选 types = 2
│
└─ "证书" / "资质" / "资格证"
   └─ 是 → 关联查询，筛选 types = 3
```

## 💡 最佳实践

1. **禁止使用 AS 中文别名**：系统会自动将原始字段名转换为中文显示名，不需要手动加别名
2. **避免同名字段冲突**：JOIN 查询不选 `p.id`，不同时选两个表的 `education`
3. **默认使用关联查询**：当用户说"档案"时，优先使用 LEFT JOIN
4. **明确字段选择**：避免使用 `SELECT *`，明确列出需要的字段
5. **适当排序**：档案记录按类型和时间排序，便于阅读
6. **处理空值**：使用 LEFT JOIN 确保基本信息总是能查出来
7. **性能考虑**：大量数据时添加 LIMIT，避免返回过多行
